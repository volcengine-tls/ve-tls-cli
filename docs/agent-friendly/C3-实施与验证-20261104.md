- 不承诺跨页快照一致性或游标永久有效；不凭空生成游标或 SQL OFFSET。

## SearchLogs 与导出

接口依据为已下载的官方文档 `/tmp/tlsdoc/日志服务/zh/API 参考/日志管理/SearchLogs.md`，重点核对了返回参数中的 ResultStatus、ListOver 和 Context：

- 纯检索用 ListOver 判断是否取尽；缺少 ResultStatus 的旧响应仍须有可信结束信号。`ListOver=false` 且无 Context，或既无结束信号也无游标，不会被当成完整。
- SQL/分析只有 `ResultStatus=complete` 才标记完整，不能用 ListOver 或 Context 推断。缺失状态为 `unknown_completion`，不自动改写 SQL 的 LIMIT/OFFSET。
- `incomplete` / `time_out` 返回非零和已获取行；`error` 返回 `server / SearchResultError`。未知状态、错误状态或无可靠位置时不提供臆测的续取描述。
- 纯检索导出保留默认 500 条/页、100 页预算。到达预算时返回下一页 Context；后续 HTTP/transport/decode 失败时，若已知当前请求游标，则续取指向失败页原请求，不跳过该页。
- raw、tool 和 human SearchLogs 共用完整性判断。human 的 host-group/collector 分页错误也以信封保留部分行，避免旧错误渲染再次丢失结果。

## 文件与交付失败

- 流式导出逐行编码，短写回滚到上一完整记录；JSON 数组结束后才交付，JSONL 保持完整行。
- 不完整数据保留在唯一的 `.<name>.partial-<random>.json/jsonl` 路径，并写入 `<partial>.meta.json`；工件描述包括 `complete`、`completeness`、`itemCount` 和可用时的 `metadataPath`。
- 页号列表的部分文件保存完整错误信封，包含所有已获取行及完整性状态。部分文件使用独立路径，不覆盖指定的既有完整目标。
- 重命名或侧车写入失败仍返回 `output_failed`；有有效部分文件时保留并报告路径，侧车失败不删除数据文件。信封、工件与可写侧车的完整性状态保持一致。
- 真正的行写入失败不报告会跳过未写入行的前向游标。stdout 写失败时返回 3，stderr 尽力保留完整性和工件位置，不重发业务请求。
- 成功导出的行文件及既有文件通知格式保留；正常成功输出协议统一仍属于 C4。

主要实现位于 `internal/execution/{completeness,pagination,result}.go` 与 `internal/cli/{search_completeness,execution_bridge,log,export_partial,log_file_output,partial_result,outcome_delivery,run_render}.go`。human 列表移除了强制重写 Total 的分支；使用文档、技能说明和工具 describe 提示同步更新。
