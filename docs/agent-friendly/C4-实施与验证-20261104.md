## 默认版的新合同与兼容边界

1. **文件交付仍返回 JSON。** `raw`、`tool exec`、`workflow exec` 的 `file_forced` 和 `file_auto` 成功响应，标准输出使用已有信封字段，`data=null`，文件路径来自 `artifacts[].path`。完整业务数据或显式筛选结果保存在文件中，标准输出不再打印中文通知或业务预览。
2. **元数据保留。** 交付信封保留 action、requestId、contract_digest、warnings、target、progress、completeness 等已有信息。`summary.itemCount` 保留原计数语义；`summary.totalBytes` 是当前交付信封字节数，`artifacts[].sizeBytes` 是实际文件大小。构造通知时复制元数据，不改写已落盘的信封。
3. **早期错误可解析。** 默认版无参数、全局选项解析失败、尾部选项缺值、未知/不可用命令组、非零 usage、无效输出格式、工作目录/项目配置失败等，返回标准输出失败信封。业务未发送时为 `remoteOutcome=not_sent`，保留退出码 1/2/3 的既有角色。未知组和无法解析的全局参数不回显整段原始 argv。
4. **标量保持结构化。** 默认版 raw 的 JSON 字符串、标量、数组和 null 均放入信封 `data`；human 保留既有字符串展示。
5. **过滤范围保留。** 标准输出的显式 `--jmes-filter` 仍能返回数组、标量或 null；文件模式只把筛选值写成一个 JSON 文档，默认版另输出交付信封。`execution.projection` 仍作用于业务结果；数组投影保留原有 `items` 加服务端元数据的封装。本批没有改变投影实现。
6. **失败交付不重发业务。** 文件提交后 stdout 失败时，返回 3，并尽力在 stderr 输出 `output_failed`，保留当前 HTTP 状态、requestId、remoteOutcome 和已提交工件路径。早期错误、根/子命令帮助、版本输出的短写也有回归。

保留的展示合同包括：human 的中文文件通知、显式帮助文本、`--version` 文本、tool/workflow 的文本发现输出，以及 login/logout/sso/configure sso 的精确 JSON 形状与既有错误契约。机器读取版本使用 `version` 命令。C3 的不完整结果、非零退出、续取描述和部分工件继续适用。

## 自动化迁移

原先解析默认版 `文件: <path>` 文本的脚本，现在解析 JSON 的 `artifacts[0].path`，并读取对应文件。应同时检查 status、remoteOutcome、deliveryOutcome 和适用的 completeness。
