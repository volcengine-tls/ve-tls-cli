## 行为合同

| 场景 | `summary.remoteOutcome` | `summary.deliveryOutcome` | 主要错误类别 |
| --- | --- | --- | --- |
| 校验、构造、凭据或签名前失败 | `not_sent` | 错误信封成功写出时为 `success` | `validation` / `auth` / `config` / `decode` |
| 已进入 HTTP 调用，但传输或响应读取失败 | `unknown` | `success` | `result_unknown` |
| 标准 JSON 响应状态或非空响应体不符合协议 | `unknown` | `success` | `protocol` |
| 收到上游失败响应 | `failed` | `success` | 按 HTTP 状态/明确错误码分类 |
| 确认成功后，投影、落盘、格式或 stdout 失败 | `success` | `failed` | `output_failed` |
| 已确认部分 ingest 批次，后续批次失败或结果未知 | `partial` | 错误信封成功交付时为 `success` | `partial_failure` |
| 结果与交付均成功 | `success` | `success` | 无 |

`failed` 表示服务返回失败响应，不证明服务端没有发生任何副作用。`unknown`、`partial`、`output_failed` 及协议失败均不构成重放许可；错误提示要求先核实远端状态或修复交付。限流可以标记 `transient=true`，与 `safeToReplay=false` 分开；不会仅因状态属于 5xx 就标记为瞬时错误，HTTP 501 有专门回归。

本批保留 `accepted` 枚举，尚未为异步操作逐一提供该结果状态；明确的异步合同仍由后续批次补齐。dry-run 或空 ingest 没有发出业务请求时为 `not_sent`。

## 关键修改与回归

- **传输证据**：构造/签名前失败才标 `not_sent`；进入 HTTP 调用后的错误保守标 `unknown`，不依赖 dial/EOF/timeout 的自然语言。保留当前响应状态、请求 ID 和已读取的响应字节；gzip 初始化或读取失败同样保留证据。安全外层消息不回显请求 URL、凭据或 transport 原文，底层原因通过 `errors.Is/As` 保留。
- **当前请求状态**：每次请求在编码和客户端解析前清理旧 requestId/status/outcome；错误响应信息也回传至 CLI。上一成功批次 ID 仅进入明确命名的历史进度字段。
- **协议边界**：标准 catalog JSON 路径要求 HTTP 200，非空响应体必须为有效 JSON；保留数字精度及空响应兼容。raw 和特殊 JSONL/PB codec 保留既有 2xx、文本、空体或二进制合同；既有解码失败仍标未知，不把损坏响应计入已确认批次。
- **多批写入**：错误信封同时保留 `data.progress` 和 `summary.progress`，以及已确认的 `logs`/`batches`。进度包括 `confirmedBatches`、`confirmedLogs`、`confirmedLogOffset`、当前批次边界/outcome、总量与 `lastConfirmedRequestId`。日志偏移从 0 开始、结束位置不包含在区间内；批次序号从 1 开始。未知批次不是安全续写断点，错误与进度不回显日志正文。
- **输出失败**：业务成功后发生自动/强制落盘、投影求值、格式或 stdout 错误时保留远端成功状态；检查 `io.Writer` 的零字节和部分短写，返回非零。文件已成功落盘而通知写失败时，stderr 保留可恢复的工件路径。
- **真实管道关闭**：二进制冒烟复现了原入口被 SIGPIPE 直接终止、stderr 为空的问题；CLI 入口现处理 SIGPIPE，让 EPIPE 进入交付失败路径。新增子进程测试在一次确认写入后关闭 stdout，断言 exit 3、完整 stderr 状态及只有一次业务请求。`.gitignore` 的二进制规则限定为根目录 `/volclog`，使入口回归可正常纳入版本管理。
- **错误分类**：本地输入、过滤器和执行错误增加类型及稳定 code；外层部分失败/输出失败优先于内层原因。HTTP 400 保留 `usage`，401/403 为 `auth`，404 为 `not_found`，409 为 `conflict`，429 及明确限流码为 `throttled`，其余上游错误保底 `server`。保留上游 code/message/requestId；ingest 对可能含日志正文的上游 message/details 使用安全外层说明。认证命令既有冻结分类保持。
- **目标快照**：成功、失败、dry-run 在目标已解析时提供脱敏 `summary.target`。未解析时不填造目标；旧隐式身份兼容路径混用环境与配置档时，来源类别标记 `mixed`，不会误称为纯 profile。

两版测试均包含：首批失败、第二批 HTTP 拒绝/断连/凭据失败/损坏响应、当前响应头后读取失败、零业务请求的前置错误、实际签名与 wire 保持、stdout 短写和真实关闭管道、工件通知失败后的恢复信息。
